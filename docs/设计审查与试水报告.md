# 《达里奥创世录》英文后期方案 · 设计审查与试水报告

审查对象：`https://github.com/null0526/dario-genesis`（commit 时间 2026-10-24，public，Python，11 stars）
审查时间：2026-10-24
结论摘要：**原方案（YouDub + VSR + UVR5 + loudnorm）四分之三是多余的，且时基与执行顺序都有硬错。应整体替换为"源码数据驱动的英文重配音 + 重烧字幕"。**

---

## 第一部分：设计审查结论

### 1.1 仓库的真实性质（这决定了方案可行性）

这不是一个"视频素材包"，是一部**纯代码生成的短片**的源码残卷：

| 层 | 实现方式 | 交付形态 |
|---|---|---|
| 画面 | 网页里的 WebGL 着色器 + Canvas，Playwright 逐帧渲染（`镜头/render.py`） | 每镜头一个 `shot.html` + `设计说明.md` |
| 声音层 | Python + numpy/scipy **纯代码合成**，无采样、无素材库（`声音/synth.py` 乐器与总线库） | 五章作曲脚本 → 各出一条全片长度 48kHz 立体声 WAV |
| 旁白 | MiniMax Speech 2.8 HD 合成，逐段 mp3 | 段级音频 + 时码 |
| 字幕 | **烧进各镜头母版画面**，无独立层（`文档/遗憾与待改进.md` 第二节自认） | 硬字幕 |
| 时基 | `数据/ch*.js` 的 `window.FILMn` = 文稿 + 逐字符时码 | 全片唯一时间真相源 |

关键契约（我逐字段验证过）：

```
window.FILMn = {
  duration, fps: 30, width: 1920, height: 1080,
  parts: [{
    id, text,                  // 中文权威文稿
    start, end, duration,      // 段在全片（章内）时间轴上的绝对位置
    charTimes: [n+1 个],       // 边界数组：charTimes[i]=第 i 字起始，charTimes[n]=结束
    localCharTimes, gainDb,    // 段内相对时码、该段旁白增益
    alignmentMethod            // 对齐方法自述
  }]
}
```

**验证结果：53 个段，`len(charTimes) == len(text)+1` 命中 53/53。** 即全片 11:43 的逐字符时间边界是完整、机器可用的。

对齐方法自述为：`Offline Whisper base source-constrained cross-attention DTW`，并注明 `not listening verification`（作者没做听感复核）。这解释了为什么时码结构完整但精度只能算"够用"。

### 1.2 逐项审查：我原方案的每个决策是否成立

| # | 原方案决策 | 判定 | 问题与影响 | 调整方向 |
|---|---|---|---|---|
| A1 | 第一步做硬字幕擦除（VSR / ProPainter inpaint） | **作废** | 目标已不存在。用户已拿到 nosub 母版（实测全片无烧入字幕）。继续执行会对干净画面做二次 AI 涂抹，纯粹劣化并引入糊斑 | 整段删除。VSR/ProPainter/IOPaint 一律不用 |
| A2 | 用 Whisper ASR 重新识别中文，再翻译 | **错误** | 仓库有权威文稿 + 逐字时码。ASR 只会引入错字、断句漂移、时间抖动；对 Anthropic/达里奥·阿莫迪这类专名极易错 | 以 `数据/ch*.js` 为唯一文本与时基真相源。ASR 只保留为"抽查译稿是否漏句"的辅助手段 |
| A3 | 用 UVR5 人声分离得到伴奏 | **多余** | 声音层可源码重生成到"与成片逐采样一致"，且天然不含旁白。分离算法必然留残响与串音，且不可控 | 用重生成 `full-music.wav` 替代分离。**边界：只覆盖 0–681.67s，片尾 23s 不在内**（见 B4） |
| A4 | 英文译文译完后直接套原时间轴 | **不成立** | 声音层是"按 BPM 从某句旁白起拍"写的，音效事件钉在中文旁白的字级时刻上（`ch4.py` 里 `52.80` 这类常量就是旁白时间）。英配若自由伸缩，全片音乐卡点全错 | 英配必须**段级绝对锁定**：段 start/end 不动，译文长度受该段时长预算约束 |
| A5 | 字幕时基直接取 charTimes | **有系统性偏移** | 实测片头有一张前置标题卡（0–3.34s 纯数字静音），`数据` 里 S01 start=0.3。存在 **+3.04s 量级的整体偏移**。直接用会让全片字幕早 3 秒 | 生产前先做时基标定（互相关），得精确 offset 后整体平移（见 B3） |
| A6 | 用 YouDub-webui 一把梭（翻译+TTS+字幕+压制） | **降级为可选组件** | 它把翻译、TTS 音色、字幕样式、时间分配全包成一个黑盒。对本片这种"时基已知且极敏感"的素材，黑盒的不确定性 > 它省下的工作量 | 改为分段可控管线。YouDub 只在缺 TTS 引擎时作为备选，不做主控 |
| A7 | — | **遗漏** | 画面内还有中文文本：`04-提交申诉` 是仿真中文后台界面，`02-祖冲之割圆` 是中文纸面。英文字幕救不了画面里的中文，英文观众会看不懂关键镜头 | 三个选项，成本递增：①接受 ②加英文角标注释 ③局部遮罩重绘。**这条必须人工取舍** |
| A8 | — | **遗漏（合规）** | `LICENSE.md`：视频/封面/旁白文稿 **CC BY-NC-SA 4.0**；代码 MIT；文档 CC BY 4.0。**NC = 禁止商业使用**，YouTube 开广告/会员即违约；且要求署名 + 相同方式共享 | 发布前明确：非商用、署名原作者 @你好与那啥、标注 AI 制作、英文版以同协议共享 |
| A9 | — | **潜在 bug** | `最小示例/build_voice.py` 的 `chunk_times()` 用 `len(re.findall(r"[一-鿿]", c))` 数字数来分配时长。英文 chunk 该值为 0 → 除零 / NaN | 若复用该逻辑必须改写：按英文词数或直接用 TTS 词级时间 |
| A10 | 建议 edge-tts 作英文音色 | **修正** | 原旁白是 MiniMax Speech 2.8 HD（片尾字幕可查）。edge-tts 音质天花板与这片画面质感不匹配 | 首选 MiniMax 英文音色（音色家族一致），次选 ElevenLabs。edge-tts 只用于试听占位 |

### 1.3 一个绕不开的取舍

A7（画面内中文）和 A8（NC 授权）都不是技术问题，是策略问题，必须由你拍板。技术侧我能做到"英配 + 英字幕"在时间上完美贴合，但画面上那几屏中文后台界面，字幕帮不上忙。

### B2 试水结论一：母版真实性得到闭环确认

实测 **−16.14 LUFS** 与 README 自述的"响度标准化 −16 LUFS"吻合到 0.14 dB。这不是巧合，说明下载的 `dario-genesis-nosub-1080p.mp4` 就是同一版母带的去字幕渲染，可以放心作为唯一视频源。

同时这条数据击穿了原方案 A3 之外的另一个假设：**"嘈杂"不是电平问题**。LRA 仅 3.30 LU 说明母版已被砖墙压缩，动态范围早被压没。任何 loudnorm/dynaudnorm 都只会让声音更扁。真正的病根是 `遗憾与待改进.md` 自认的四条：点缀密度偏高、循环与点缀叠加、音色库窄（拨弦/木槌/方波）、只在手机外放口径验收。

### B3 试水结论二：发现 +3.04s 时基偏移（原方案最大隐性风险）

逐秒 RMS 剖面显示：

- `t=0,1,2` → **−inf**（真数字静音，一个采样都没有）
- `silence_end = 3.3429s`

抽帧确认 0–3.3s 是一张**片头标题卡**（"达里奥创世录 / Dario Genesis / 原作 bilibili @你好与那啥 / 本片未经 Anthropic 审核或认可"，中英双语，自带，不需要重做）。

而 `数据/ch1.js` 里 S01 `start = 0.3`。

→ 差值 **3.3429 − 0.3 ≈ 3.04s**。这张标题卡是后加的，不在 `数据` 的时间轴里。

**影响**：任何直接拿 `charTimes` 当字幕/配音时基的做法，会让全片内容早 3 秒。A5 的判定由此成立。

**标定方法（生产第 0 步）**：重生成 `full-music.wav`（681.67s），与母版音轨做互相关，峰位即精确 offset。这是唯一可靠的解法，不能靠猜。

**标定已执行，结果为 +3.05067s（146432 采样）：**

| 验证项 | 结果 |
|---|---|
| 6 个时间窗（40/150/260/380/500/600s）独立求解 | 全部 **+3.05067s**，极差 **0.000ms** |
| 峰值锐度 | 偏移改到 3.0429（差 8ms）时，相关系数从 **0.505 崩到 0.036** |
| 视频侧交叉验证 | 首切点 pts 3.04206s，与音频差 **9ms**（不足 1/3 帧） |
| 文稿侧端到端验证 | `数据` S01 预测起点 3.35s，实测语音起始 3.3429s，差 **7ms** |

三条独立证据收敛到同一位置，偏移可以定死。**换算公式：母版时间 = 章节偏移 + 段内 start + 3.05067**。

### B4 试水结论三：声音层覆盖范围有 22.3s 缺口

`splice_all.py` 硬编码 `DUR = 681.6666`。而母版时长 **703.928s**。RMS 剖面把缺口的构成说清楚了：

| 区段 | 内容 | 声音层是否覆盖 |
|---|---|---|
| 0 – 3.34s | 片头标题卡，纯静音 | 不需要（静音） |
| 3.34 – 673.0s | 正片五章 | ✅ 覆盖 |
| 673.0 – 680.0s | **7.0 秒纯静音**（−inf，正好对应最小示例 `TAIL=7.0`） | ✅ 覆盖（静音） |
| 680.0 – 703.4s | **片尾字幕卡 + 配乐，23.4s** | ❌ **不在 composer 脚本范围内** |

抽帧确认 690s 处是片尾名单（导演 Claude Opus 5.5 / 作曲 Claude Sonnet 5.5 / 技术 GPT-6.1 Sol / 旁白 MiniMax Speech 2.8 HD / 出品人 一位前 Claude Max 5x 用户）。

**影响**：如果按 A3 走"重生成伴奏"路线，最后 23 秒会**静音**——正好是片尾曲，观感事故。
**调整**：这 23 秒必须单独处理。最省事的是从母版音轨**直接截取**（该段没有中文旁白，只有纯配乐，截出来就是干净 bed），拼在重生成的 681.67s 之后。这样既不需要作曲家脚本，也不损失任何东西。

### B5 试水结论四：英文稿的量化预算是可行的

2535 个中文字 / 678 秒旁白 ≈ **3.74 字/秒**，折合正常英文语速约 **150 wpm**。反推英文稿目标长度 **1600–1750 词**。这个密度与中文原稿相当，说明**英文不需要整体加速就能塞进原时间轴**——A4 的段级锁定方案在物理上可行，不需要靠时间伸缩硬压。

## 第三部分：后期处理整体思路与执行规格

### 3.1 为什么只处理已有视频，不重新生成视频

三条理由，从硬到软：

1. **不可行。** 全片约 40 个镜头，仓库只放了 4 个母版原型；成片还经过"按旁白逐字重映射时钟、统一胶片颗粒、拼接调色"，这些脚本绑着原制作目录，README 明确说没放进来（"不是一键重现整部片的流水线"）。重生成连素材都不齐。
2. **不必要。** 我们要改的只有两样东西：**音轨**（换旁白语言）和**字幕层**（加英文字幕）。这两者与视频流完全解耦——画面不需要知道旁白在说什么。母版已经是 1080p30、无烧字幕、无黑边、时长完整的干净成品。
3. **有风险。** 重生成意味着重跑 WebGL 逐帧渲染 + 重新对齐 + 重新调色，任何一处偏差都会让成品与已发布版本产生不可控差异。而后期处理是**可逆、可增量、可 A/B** 的。

一句话：**画面归画面，声音归声音。** 这个片的画面是"无声的插画"，声音是"独立的合成层"，本来就不耦合，硬要绑在一起重做是自找麻烦。

### 3.3 七步执行链

**S0 · 时基标定**
重生成 `full-music.wav`，与母版音轨互相关，求精确 offset（预期 +3.04s）。
产出：`timebase.json`（全局映射表）。**这一步不做，后面全是错的。**

**S1 · 拆轨**
从母版解出完整音轨 → 切成 `head`(0–3.34) / `body`(3.34–673) / `tail`(673–703.4)。
产出：`master.wav`、`tail_bed.wav`（片尾纯配乐，直接复用）。

**S2 · 译稿（约束写作）**
按 53 段逐段翻译，每段给定硬预算：`预算时长 = 原段 duration`；`预算词数 ≈ 原段中文音节数 × 系数`。
产出：`script_en.py`（沿用 `最小示例/script.py` 的结构，段 id 与中文一一对应）。
验收：每段英文 TTS 试读时长落在 `duration × [0.92, 0.98]`（留 2–8% 余量给换气）。

**S3 · 英配合成**
分段 TTS（段边界固定，不跨段合并）→ 段内若偏长，用 `atempo 0.95–1.05` 微调；超出 ±5% 退回改译，不硬压。
产出：`tts_en/{id}.mp3` + `timeline_en.json`（段级 start/end + 块级时码）。

**S4 · 拼装**
按**原始** `start` 绝对位置铺英文干声（不是顺序拼接），与 S0 的 offset 对齐。
产出：`voice_en.wav`（全片 703.928s，只在原旁白时间窗内有声）。

**S5 · 混音**
重建 README 记录的原比例关系：声音层 **−4.49 dB** 后与旁白相加。
按 `遗憾与待改进.md` 的四条病根做定向修正：bed 整体再降 2–4 dB、点缀密度减半、对旁白做侧链压缩（让 bed 在人声时自动让路）。
收尾 loudnorm 到 **−14 LUFS / TP −1.5 dBTP**（YouTube 标准；原片 −16 是 B 站口径）。
产出：`mix_final.wav`。

**S6 · 字幕**
沿用原作样式参数（`make_ass.py`）：1920×1080、MarginV=60、单行、描边 0 阴影 0、双色样式按章节切换。
字体从 `Noto Sans SC 62px` 换成 `Inter / Source Serif 4`，字号按英文 x-height 重算（约 54–58px）。
时码由 `charTimes` 边界查表 + S0 offset 平移得到，**不用字数比例估算**（A9 的 bug 由此绕开）。
产出：`subs_en.ass` + `subs_en.srt`。

**S7 · 合成输出**
视频流 `-c:v copy` 直通（零重编码损失）；音频 AAC 192–256k；字幕两条路都出（烧入版 + 软封装/外挂）。

### 3.4 同步机制（三层锁定）

| 层 | 锚点 | 容差 |
|---|---|---|
| 段级 | `charTimes[0]` 与 `end`，加 S0 offset | ±40ms（1 帧 33ms） |
| 句块级 | 按原 `chunks` 在 `charTimes` 里查表取边界 | ±100ms |
| 词级 | TTS 自带 word boundary，或 Whisper 回读校验 | ±150ms |

核心原则：**英文覆盖的时间窗 = 原中文旁白的时间窗**。音乐卡点、画面事件全部钉在这个窗上，窗不动，卡点就不会错。

### 3.5 输出成品规格与质量红线

**视频**
- 容器 MP4 / H.264 High / 1920×1080 / 30fps / yuv420p / BT.709 / `+faststart`
- 视频流直通 copy，不重编码（避免二次有损）
- 时长锁定 703.928s，±0 帧

**音频**
- AAC-LC 48kHz 立体声，192–256 kbps
- **−14 LUFS ±0.5**，True Peak ≤ −1.0 dBTP，LRA ≥ 7 LU
- 无削波、无爆音、无人声与 bed 的相位抵消

**字幕**
- 单语英文（不做中英双语，画面里已经没有中文可对照）
- 单行 ≤ 42 字符，CPS ≤ 20，最短停留 0.8s
- 不跨镜头硬切（在 `chunks` 边界处断句，而非按宽度硬切）
- 交付 ASS（保留样式）+ SRT（平台通用）两份

**验收方法**
- 机器：`ffmpeg ebur128` 查响度；`silencedetect` 查空档；逐段比对 TTS 时长 vs 预算
- 人工：随机抽 10 段做 A/B 听感；三个镜头（割圆/黑洞/申诉）目视核对字幕不出画、不压字

## 附：一句话总结

原方案是在"拿不到干净母版、拿不到文稿、拿不到分轨"的前提下做的妥协设计。现在三个前提全部反转——**母版是干净的、文稿和逐字时码是完整的、伴奏是可以逐采样重生成的**——所以正确的方案不是"优化 YouDub 流水线"，而是**抛弃它**，改用数据驱动的重建：换旁白、换字幕、复用画面，一步不多。
